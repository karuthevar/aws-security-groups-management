# Executive Leadership Portal Specification

## 1. Executive Objective & UX Requirements

Security audits across multi-account AWS Organizations produce large quantities of raw technical data. Leadership requires a clean, interactive mini-website / portal that:
1. **Runs Locally with Zero Setup**: Double-clickable in any modern browser (`portal/index.html` or `executive_leadership_portal.html`) without running local web servers or installing node modules.
2. **100% Offline Capable**: Zero CDN links (`cdnjs`, `google-fonts`, `tailwindcss`). All CSS styles, vector SVGs, and JavaScript logic must be fully embedded within the HTML file.
3. **No Timelines**: Zero calendar dates, days, or time estimates. All prioritization is strictly driven by **Operational Impact & Downtime Risk** and **Implementation Complexity**.
4. **Interactive Multi-Dimensional Filtering**: Real-time filtering by:
   * **Domain**: Network, IAM, Storage, Database, Logging & Monitoring.
   * **Operational Impact**: Zero-Impact Quick Wins, Low-Impact Review, High-Risk Planned Window.
   * **Severity**: Critical, High, Medium, Low.
   * **Account**: Account concentration filter showing findings per AWS Account ID / Name.
5. **Action-Oriented Detail View**: Each finding must show:
   * Clear root cause and risk narrative.
   * Exact AWS CLI remediation command.
   * AWS Config managed rule name.
   * AWS Organization Service Control Policy (SCP) guardrail.
   * Downtime impact assessment note.

## 3. Automated Portal Generation

The portal is automatically regenerated by running the consolidation script:
```bash
python scripts/build_executive_portal.py \
    --reports-dir ./reports \
    --output ./portal/index.html
```
The generator parses all recent JSON audit manifests, deduplicates findings, calculates compliance indices per account, and writes the self-contained HTML file.
